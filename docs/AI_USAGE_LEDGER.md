# FIS Learning — study actions and AI request ledger

## Reproduction before the change

On disposable PostgreSQL `fis_quota_baseline_20261123`, we exercised the then-current 48-attempt policy with 12 attempts remaining. Three simulated questions used an embedding, rerank, generation and one generation retry each. The test recorded 12 attempts and the following quiz authorization returned HTTP 429. It modeled the reported failure without making external calls or altering the learner's active workspace. In earlier local logs, a guest had reached 12 recorded attempts even though the workspace had room.

## Request flow

| Study action | FIS requests and database operations | External work on a successful first pass | What is counted and reused |
|---|---|---|---|
| Upload one PDF | Check session, create or select course, reserve an upload, transfer the file and finalize. Processing leases extract text, index chunks and persist an outline. | Private Blob write, metadata and byte reads. Document embeddings in batches of 16 on a cold index, if eligible. Large uploads get a scoped client token first. | One completed upload when the PDF is finalized. Blob actions use Blob limits. Embeddings count toward provider capacity. Matching chunks in the same course and processing version reuse an eligible stored embedding space. |
| Ask a document question | Authenticate and validate, claim an action, search PostgreSQL for owned `READY` material, run the tutor and save the turn. Opening a source reads an authorized existing PDF or chunk. | At most one query embedding on a single-space course before generation on the ordinary first pass. Hybrid retrieval uses a local FTS and vector merge. Each eligible fallback creates another provider attempt. | One completed question. Query embedding and generation are separate provider attempts. Source navigation creates zero AI attempts. |
| Use a contextual follow-up | Verify the stored conversation and prior reply, resolve the same currently visible citations and run the tutor. A visual question about exact source measurements may be answered locally. | One generation if the stored sources are usable and a model is needed. A local measurement explanation needs zero AI calls. If citation reuse is invalid, run retrieval again. | One completed question. Valid reuse avoids the query embedding and ranking; no second model call formats the reply. |
| Start Quick Quiz | Authenticate, check course/topic, claim the quiz action and use stored course sources. Validate questions and cited source IDs, then save the quiz and mark the action complete in the same transaction. | One structured generation in the default course-wide quiz. A selected topic can need a query embedding. | One completed quiz. Replaying its idempotency key opens the stored quiz with zero extra calls. Concurrent duplicate requests receive a conflict until the first request settles. |
| Submit or reopen a quiz result | Validate and save answers, grade locally, update progress once with the submission key, then return feedback from saved assessment and currently owned sources. | Zero AI calls. | Assessment and submission are tracked by `QuizAttempt`, `StudentAnswer` and `AssessmentResult`. One result remains available after refresh if the owner session is active. |
| Listen | Validate the selected reply text, claim a Listen action, synthesize and return private audio. | One synthesis before eligible fallback. | One completed Listen. An identical retry may replay private audio for up to ten minutes. Expired replay bytes are cleared on a subsequent Listen request or account deletion. |

`AiAction` records the owner, kind, payload fingerprint, lease, outcome and saved result reference. It records local retrieval/source reuse separately from model requests. `AiProviderAttempt` records the gateway, model, endpoint, operation, latency, status, rate scope, category, retry timestamp, and request/token counters when provided. The provider reservation and audit row are atomic. An invocation interrupted outside the process can retain a `started` row because the final upstream outcome is unknown. The ledger never stores prompts, API keys, provider error payloads, or source text. Listen replay is owner-scoped derivative data with the short replay window above.

Live retrieval uses hybrid. The controlled benchmark retains separate vector and rerank variants. In the 50-question run, Recall@5 was 80.68% vector-only and 93.56% for both hybrid variants. Rerank was invoked once and raised nDCG from 0.92486 to 0.92732. The live path saves one provider attempt on each question that previously crossed the rerank threshold. It saves zero on questions that already skipped it. A warm duplicate upload test used one embedding call across two identical uploads. A quiz replay avoids a second generation.

Provider selection stays verified-free for automatic routing. Shared OpenRouter pool, OpenRouter account, Gemini and Groq quota boundaries use provider metadata and reset hints where available. Workspace usage budgets still apply when provider quota information is absent. A provider with an unsupported capability is ineligible. The status endpoint shows public availability and owner-scoped diagnostics without exposing other learners' usage. See [provider configuration and limits](AI_MODELS.md).

## Acceptance evidence, 24 November 2026

- A brand-new browser guest used the local production build and a separate loopback PostgreSQL database. The synthetic PDF reached `READY` on private Preview Blob storage, and the authorized copy matched the input bytes. Signed-out fetch returned `401`. All three answers matched facts in the PDF, and the citation for a `2 N` load and `4 cm` extension opened page 1. Listen loaded a 14.84-second reply. Quick Quiz generated three questions, replayed the same quiz ID with the original request key, saved the result, reopened it after reload, and reopened it again from Progress. Zero page errors and zero paid inference attempts were observed. The disposable account was cleaned up.
- The workspace counter recorded nine provider attempts for that entire guest journey. Each of the three questions used two attempts. Speech and quiz generation used one each. Upload indexing used the remaining attempt. Quiz submission and replay made no provider calls. The learner completed three chat actions and one quiz action, independently of indexing and speech.
- Gemini 3.5 Flash-Lite and Gemini Embedding 2 served the live guest route, and OpenRouter served Fish Audio S2.1 Pro Free. Separate same-build text smoke tests returned `200` and saved the requested route for Groq GPT-OSS 20B and OpenRouter NVIDIA Nemotron 3.5 Super VL Free.
- The controlled production-build harness passed 5/5 and 10/10 simultaneous sessions. Journey p95 was 316 ms and 522 ms. A simulated OpenRouter Google AI Studio upstream pool `429` skipped the affected sibling model, fell back to free NVIDIA, and allowed a later request to NVIDIA. The transport recorded zero paid requests. Quiz replay made zero additional provider calls, and another account was denied access to the saved result. These timings describe the controlled environment.
- `npm run typecheck`, `npm run lint`, `npm run build`, `npm run db:deploy`, and `npm run eval:retrieval` completed. `npm test` passed 98 of 98 across 13 files with the migrated isolated database. `npm run test:e2e` passed 11 of 11. The build ran in an isolated staging copy with a temporary Turbopack root for the dependency junction. Application and schema sources matched the repository. Logs and snapshots are in the local artifact folder `FIS Local Run/Guest ledger acceptance`.
- The read-only OpenRouter key check at 12:35 Cairo time reported 49 of 50 daily free requests remaining. This snapshot is independent of FIS action and work budgets and can change with subsequent requests. [OpenRouter limits](https://openrouter.ai/docs/api/reference/limits)
