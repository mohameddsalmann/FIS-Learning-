# AI routing

The gateway matches capability, recorded provider and model health, eligibility and request budget before making an inference call. Automatic routing prefers compatible healthy Gemini, GroqCloud, and OpenRouter routes in that order. The server exposes eligible model metadata and coarse provider status at `/api/learning/models`. Manual selection stays in Advanced Settings.

## Provider configuration

- **Google Gemini.** Set `GEMINI_API_KEY_PRIMARY`, or use `GOOGLE_API_KEY` or the legacy `GEMINI_API_KEY`. Set `GEMINI_PRIMARY_FREE_TIER_CONFIRMED=true` only after verifying the key's project has no paid Gemini tier. The app checks Gemini model capabilities with the official Google Gen AI SDK. The allowlist includes Gemini 3.5 Flash-Lite, Gemini 3.8 Flash, Gemini 3.6 Flash, and Gemini Embedding 2. Text, image, supported video, JSON, and embeddings use dedicated SDK methods. Embeddings are indexed at 2048 dimensions. A distinct secondary key requires its own Free-tier confirmation and is used for an authentication failure only. A Gemini 429 can fall back to another provider, without rotating Gemini keys. [Google API keys](https://aistudio.google.com/docs/api-key), [Gemini pricing](https://aistudio.google.com/docs/pricing), [Gemini rate limits](https://aistudio.google.com/docs/rate-limits)
- **GroqCloud.** Set `GROQ_API_KEY` or `Groq_API_KEY`. Enable it with `GROQ_FREE_PLAN_CONFIRMED=true` after verifying the organization plan. The app checks the active catalog for GPT-OSS 20B and 120B. The adapter handles text streaming and JSON with on-demand service, and honors `Retry-After`. Image and video stay on compatible providers. [Groq model catalog](https://console.groq.com/docs/models), [Groq rate limits](https://console.groq.com/docs/rate-limits)
- **OpenRouter.** Set `OPENROUTER_API_KEY`. The adapter requires an exact, current zero-price route for the capability and uses a provider price ceiling where supported. Dedicated endpoints handle speech, image generation, decisions, embeddings and reranking. A personal OpenRouter key is scoped to eligible OpenRouter routes for the active page session. Its value is kept out of persisted preferences and public logs.
- **xAI.** Inference starts disabled. An authorized operator can configure `XAI_API_KEY`, a pinned `XAI_MODEL` and `XAI_INFERENCE_MODE=verified_zero_cost` or `paid_authorized`. The zero-cost mode requires complete relevant zero-price metadata. A paid model requires explicit manual selection. xAI remains outside automatic fallback. [xAI model API](https://docs.x.ai/developers/rest-api-reference/inference/models)

## Runtime limits

A guest can complete 24 questions, 8 generated quizzes, 12 Listen requests and 5 uploads per UTC day. Signed-in limits are 48, 16, 24 and 30. Stored-file and guest sign-in limits are separate. PostgreSQL also reserves provider work per request. Defaults are 120 attempts per workspace per UTC day, 90/160 per guest/account per day and 24/40 per minute. The shared OpenRouter route additionally has an operator-configured daily cap (default 50) and 20 per minute. Upstream limits apply independently. The gateway uses at most four attempts per operation and prefers eligible providers that have yet to be tried. It stores cooldowns by affected resource in PostgreSQL. Status details and request flows are in [AI usage ledger](AI_USAGE_LEDGER.md).

Document retrieval keeps compatible embedding vectors in separate model spaces. NEON/Blob requirements and HTTPS release gates are in [Deployment](DEPLOYMENT.md). Browser dictation still depends on the browser. Dedicated speech recognition and provider-assisted media output depend on an eligible route.
